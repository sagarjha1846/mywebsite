Architecture

Correctness shouldn't depend on everyone remembering.

The patterns I reach for, and the one idea underneath all of them: put the rule where it can't be bypassed, not in a document that asks people to be careful.

  • Outbox pattern

    State change and its event committed in one transaction — no dual-write window.

  • Permission-tree resolution

    One server-side authority the API guard and the UI both read from.

  • Idempotent consumers

    Effectively-once processing on top of at-least-once delivery.

  • State machines in the database

    Transition rules enforced where the write happens, for every caller.

  • Append-only audit trails

    Tamper-evidence by construction — no mutation path in the codebase.

  • Module Federation

    Independently built and deployed frontends composed at runtime.

About

I work at the layer where a mistake is expensive. Authorisation, approvals, audit trails, identity — the systems that other features quietly assume are correct.

That started at a supply chain finance company, where I built RBAC, a multi-stage approval engine and an event-driven notification system from scratch because every new product was rebuilding them badly. It ended up as the foundation the product ecosystem was built on, and generalising it into domain-agnostic services is a large part of what I do now.
